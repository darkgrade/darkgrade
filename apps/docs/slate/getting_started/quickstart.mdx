## Before you connect

- Put the camera in its USB remote-control mode.
- Close other applications that hold the camera. Only one program can own its USB session at a time.
- On Linux, your user needs permission to open the USB device.

## Basic Usage

```typescript
import { Camera } from '@darkgrade/slate'

const camera = new Camera()
await camera.connect()
try {
    const { controls } = await camera.getCapabilities()
    if (controls.iso?.writable && controls.iso.allowedValues?.includes('ISO 800')) {
        const observed = await camera.setControl('iso', 'ISO 800')
        console.log(observed.value)
    }
    const { data } = await camera.captureImage()
    if (!data) throw new Error('No image data returned')
} finally {
    await camera.disconnect()
}
```

The `Camera` class automatically detects your camera's brand and uses the appropriate vendor-specific implementation. The example assumes the body advertises those controls and remote capture; camera model, USB mode, and shooting mode can change the available surface.

For application UIs, use the [shared control model](/slate/getting_started/controls):
`getCapabilities()` exposes current choices across vendors, and `shutterSpeed`
covers exposure duration and shutter angle without implicit mode changes. Multiple USB
bodies require an explicit device filter.

For a generic or Olympus body, inspect the live standard-property inventory first:

```typescript
const properties = await camera.getStandardPropertyStates()
const iso = properties.find(property => property.name === 'ExposureIndex')
if (iso?.writable) await camera.setStandardProperty('ExposureIndex', 'ISO 800')
```

This prevents an application from presenting ISO, aperture, or focus controls solely because it recognizes a vendor name. For example, the physically tested Olympus E-PL5 MTP mode publishes battery and camera date/time but no exposure or remote-capture property.

## How It Works

When you call `connect()`, Darkgrade Slate:

1. Scans for connected USB devices
2. Identifies the camera's vendor ID
3. Selects the appropriate vendor-specific implementation:
   - **Sony ⍺ Series** → `SonyCamera` with live view, video recording, SDIO
   - **Nikon Z Series** → `NikonCamera` with extended properties
   - **Canon EOS R Series** → `CanonCamera` with remote control
   - **Olympus and other PTP cameras** → `GenericCamera` with a capability-driven standard-property inventory
4. Opens that driver's session. Read `getCapabilities()` for current controls and write guards.

## Common Examples

### Camera Settings

```typescript
// Get current settings
const currentIso = await camera.getIso()
const currentShutter = await camera.getShutterSpeed()
const currentAperture = await camera.getAperture()

// Set new values; each resolves to the value the camera read back
await camera.setExposureMode('Manual')
await camera.setIso('ISO 1600')
await camera.setShutterSpeed('1/500')
await camera.setAperture('f/4')
await camera.setExposureCompensation('+0.7')
```

Values use one spelling on every camera: `'f/4'`, `'ISO 1600'` or `'Auto'`, `'Manual'` or
`'Aperture priority'` (`M`/`A`/`S`/`P` and Canon's `Av`/`Tv` are accepted too), `'+0.7'`, `'Spot'`.
`getCapabilities().controls` lists the choices this camera offers now.

### Event Handling

```typescript
// Listen for camera events
camera.on(camera.getInstance().registry.events.ObjectAdded, event => {
    console.log('New object added:', event.ObjectHandle)
})

camera.on(camera.getInstance().registry.events.DevicePropChanged, event => {
    console.log('Property changed:', event.DevicePropCode)
})

// Remove event listeners
camera.off(camera.getInstance().registry.events.ObjectAdded)
```

### Live View

Capture live view on supported Sony, Nikon or Canon bodies:

```typescript
const { data: liveViewFrame } = await camera.captureLiveView()
if (!liveViewFrame) throw new Error('No live-view image returned')
fs.writeFileSync('liveview.jpg', liveViewFrame)
```

### Video Recording

Start and stop video recording on supported Sony, Nikon or Canon bodies with usable media:

```typescript
await camera.startRecording()
// ... record for some duration ...
await camera.stopRecording()
```

A successful stop means the camera acknowledged the command; it does not verify the saved movie. Check the file on the card before relying on a take. If a start fails, treat the recording state as uncertain until a stop succeeds.

### File Management

List and download files from the camera:

```typescript
const objects = await camera.listObjects()

for (const [storageId, storage] of Object.entries(objects)) {
    console.log(`Storage ${storageId}: ${storage.info.storageDescription}`)
    
    for (const [handle, info] of Object.entries(storage.objects)) {
        console.log(`  - ${info.filename} (${info.objectCompressedSize} bytes)`)
        
        // Download a specific object
        const fileData = await camera.getObject(Number(handle), info.objectCompressedSize)
        fs.writeFileSync(info.filename, fileData)
    }
}
```

### Advanced Property Access

Access vendor-specific properties directly:

```typescript
const registry = camera.getInstance().registry

// Get property with type safety
const propValue = await camera.get(registry.properties.ExposureIndex)

// Set property
await camera.set(registry.properties.ExposureIndex, '3200')
```

## Advanced Usage

### Typed protocol access

Applications instantiate `Camera` and use its shared control model. Protocol work can
use the existing typed definitions without maintaining an application vendor map:

```typescript
import { Camera, genericOperationRegistry } from '@darkgrade/slate'

const camera = new Camera()
await camera.connect()
try {
    const reply = await camera.send(genericOperationRegistry.GetDeviceInfo, {})
    console.log(reply.data)
} finally {
    await camera.disconnect()
}
```

### Manual Configuration

Specify device filters and logging options:

```typescript
import { Camera, VendorIDs } from '@darkgrade/slate'

const camera = new Camera({
    device: {
        usb: {
            filters: [{ vendorId: VendorIDs.SONY }], // VendorIDs.NIKON, VendorIDs.CANON
        },
    },
    logger: {
        renderInTerminal: true,
        captureConsole: false,
        expanded: true, // Show detailed logging
    },
})

await camera.connect()
```

## Errors and recovery

Transactions are bounded by timeouts, replies are checked against PTP container framing, and failures are typed (`PTPTimeoutError`, `PTPProtocolError`, `PTPDecodeError`, `PTPResponseError`, `PTPDisconnectedError`, `PTPRecoveryRequiredError`). Tune them with `new Camera({ transactionPolicy: { timeoutMilliseconds, deviceBusyRetries } })`. After a USB timeout or framing violation, the next command first sends the still-image class Device Reset Request, waits for the abandoned I/O to settle and reopens the session. Only if that automatic reset fails, or on PTP/IP (which has no class reset), do further commands fail with `PTPRecoveryRequiredError` until a disconnect/connect. Set `automaticUSBReset: false` to keep the latch, or supply `recoverTransport` to replace the reset with your own recovery (for example one that honors recording guards).
