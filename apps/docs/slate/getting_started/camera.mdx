---
title: "Cameras"
description: "One Camera that works the same on every camera that supports an operation: connection, settings, focus, zoom, photo, live view, video, card and body."
---

`Camera` picks the Sony, Nikon, Canon or standard PTP driver when it connects; no method is named
after a vendor. Every method has the same name as an MCP tool (`camera_` and the method in
snake_case) and a command (`darkgrade camera` and the method in kebab-case), all generated from one
operation table. [Feature compatibility](/slate/getting_started/feature-compatibility) lists which
cameras support each operation; `getCapabilities().operations` says whether the attached one can
do it now.

## Import

```typescript
import { Camera } from '@darkgrade/slate'
```

## Constructor

```typescript
constructor(options?: CameraOptions)
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| **options** | `CameraOptions` |  | Optional configuration for the camera instance. |
| **options.logger** | `Partial&lt;LoggerConfig&gt;` |  | Optional logger configuration; console capture and terminal rendering are off by default for `Camera`. |
| **options.device** | `DeviceDescriptor` |  | The body to open, for example a USB filter when several are attached. |
| **options.transport** | `TransportInterface` |  | A transport other than USB, such as an `IPTransport` (see [PTP/IP](/slate/getting_started/ptp-ip)). |
| **options.transactionPolicy** | `Partial&lt;TransactionPolicy&gt;` |  | Timeouts and DeviceBusy retries for every transaction. |
| **options.keepAlive** | `boolean` |  | Default `true`: a Canon session sends its advertised KeepDeviceOn every ten seconds. |

## Errors

Every operation fails in one of three ways, each carrying the `operation` that failed:

| Error | Meaning |
| ----- | ------- |
| `CameraUnsupportedError` | This camera cannot do it right now; `getCapabilities()` says why. Nothing was sent. |
| `CameraRefusedError` | The camera said no, or the value is not one it offers now. Nothing changed. |
| `CameraOutcomeUnknownError` | The command was sent but its result could not be confirmed. It is never resent, so a photo or a Stop is never repeated by accident. `CameraConfirmationError` (a setting that did not read back) and `CameraClipNotFoundError` (stopped, but no new clip appeared) are kinds of it. |

## Connection

### discover

List attached USB cameras without opening one. `camera_discover`, `darkgrade cameras`.

```typescript
static async discover(): Promise&lt;DiscoveredCamera[]&gt;
```

### connect

Open the camera: select the attached body, its driver and a session.

```typescript
async connect(options?: ConnectOptions): Promise&lt;void&gt;
```

| Option | Type | Required | Description |
| ------ | ---- | -------- | ----------- |
| **observeOnly** | `boolean` |  | Read without changing any setting. Sony keeps its dial priority and saved image destination. Default `false`. |
| **device** | `DeviceDescriptor` |  | The body to open. If not provided, uses the device from the constructor options; with neither, opens the one attached PTP camera of any vendor. |

### disconnect

Close the camera and put it back the way it was.

```typescript
async disconnect(): Promise&lt;void&gt;
```

### recover

Unstick a camera that stopped answering, in software: a fresh session, a PTP Device Reset, then a
USB port reset, each proven by GetDeviceInfo. The report says whether it worked and when only
unplugging or a power cycle is left. The transport is closed afterwards; call `connect()` again.

```typescript
async recover(): Promise&lt;RecoveryReport&gt;
```

### getInfo

What the body reports about itself: manufacturer (`'Sony'`), model, firmware, serial number when
reported, the lens mount where the model implies it, and the connection (`'usb'`, `'wifi'` or `'ip'`).

```typescript
async getInfo(): Promise&lt;CameraInfo&gt;
```

## Settings

### getCapabilities

Every setting's current value and choices (`controls`), which operations this camera can do right
now with the reason when not (`operations`), and the lens and its focal length (`lens`). It is an
observation of this body in its current mode, not a model-level guarantee.

```typescript
async getCapabilities(): Promise&lt;CameraCapabilities&gt;
```

### setControl

Set any setting by id, for UIs that list every setting. Resolves to the confirmed observation.
See the [shared control model](/slate/getting_started/controls).

```typescript
async setControl(id: CameraControlId, value: string | number | ExposureTime, context?: { framesPerSecond: number }): Promise&lt;CameraControlState&gt;
```

### Typed getters and setters

Each setting has `get<Setting>()` and `set<Setting>(value)`. The setter is `setControl` for that id:
it takes only canonical values (a compile error otherwise), refuses a value this camera does not
offer now before sending anything, writes once and resolves to the value read back.

| Setting | Methods | Example values |
| ------- | ------- | -------------- |
| Shutter speed | `getShutterSpeed` / `setShutterSpeed` | `'1/250'` `'30"'` `'180°'` `'Bulb'` |
| Aperture | `getAperture` / `setAperture` | `'f/2.8'` `'Auto'` |
| ISO | `getIso` / `setIso` | `'ISO 800'` `'Auto'` |
| Exposure mode | `getExposureMode` / `setExposureMode` | `'Manual'` `'Aperture priority'`; `M` `A` `S` `P` `Av` `Tv` accepted |
| Exposure compensation | `getExposureCompensation` / `setExposureCompensation` | `'+0.7'` `'-1.0'` `'0.0'` |
| Metering | `getMeteringMode` / `setMeteringMode` | `'Multi'` `'Spot'` |
| Photo / video | `getPhotoVideoMode` / `setPhotoVideoMode` | `'photo'` `'video'` |

| Look | `getPictureStyle` / `setPictureStyle` | `'Standard'` `'Portrait'` |
| Picture profile | `getPictureProfile` / `setPictureProfile` | `'PP8'` |
| Focus mode | `getFocusMode` / `setFocusMode` | `'AF-S'` `'AF-C'` `'MF'` |

| Subject detection | `getSubjectDetection` / `setSubjectDetection` | `'On'` `'Off'` |
| Continuous AF | `getContinuousAutofocus` / `setContinuousAutofocus` | `'On'` `'Off'` |
| Detection subject | `getDetectionSubject` / `setDetectionSubject` | `'People'` `'Animals'` |
| Eye selection | `getEyeSelection` / `setEyeSelection` | `'Auto'` `'Left'` |

The examples are illustrative; the exact lists come from the vendor codecs, and
`getCapabilities().controls.<setting>.allowedValues` lists only what this camera offers now.
A shutter angle and a duration convert to each other only with the actual frame rate:

```typescript
async setShutterSpeed(value: ShutterSpeed | ExposureTime, context?: { framesPerSecond: number }): Promise&lt;ShutterSpeed&gt;
```

`setIso` on a Sony body with a separate auto/manual gain switch switches it as part of the write
(the one recorded exception to "a setting write never changes another setting"). Sony's extended
and Multi Frame NR sensitivities keep their own names (`'ISO 51200 (extended)'`,
`'Multi Frame NR ISO 800'`). A Sony body in movie mode reads `'Manual'` for Movie Manual and
offers only its movie modes.

## Focus

```typescript
async autofocus(): Promise&lt;'acquired' | 'not-acquired' | 'unknown'&gt;
async setFocusPoint(x: number, y: number, options?: { autofocus?: boolean }): Promise&lt;void&gt;
async resetFocusPoint(): Promise&lt;void&gt;
async nudgeFocus(direction: 'near' | 'far', size: 'small' | 'medium' | 'large'): Promise&lt;{ atLimit: boolean }&gt;
```

`autofocus` focuses once and says whether the camera confirmed focus; only `'acquired'` means it
did. `setFocusPoint` takes 0–1 from the top-left of the picture and focuses there unless
`autofocus: false`; switching to a movable focus area happens inside and `resetFocusPoint` puts
back the centre and the previous focus area. `nudgeFocus` moves manual focus a little, like the
`<` `<<` `<<<` buttons in vendor remote apps; `atLimit` says the lens reached the end of its focus
travel that way (it moved less than the step, or not at all), which is a completed nudge, not an error.

## Zoom

```typescript
async zoomTo(focalLengthMillimetres: number): Promise&lt;number&gt;
async startZoom(direction: 'in' | 'out', options: { speed: 'slow' | 'medium' | 'fast' }): Promise&lt;void&gt;
async stopZoom(): Promise&lt;void&gt;
```

`zoomTo` zooms to a focal length ("go to 35") and resolves to where the lens landed, read back.
`startZoom` zooms until `stopZoom`, like holding a zoom rocker; Slate stops it by itself after
10 seconds. `stopZoom` is always allowed. On the command line, use `zoom-to`.

## Photo and live view

### takePhoto

Takes one photo and resolves only once the camera shows the new file. Photo or video mode is
prepared inside and undone afterwards; the shutter command is never resent.

```typescript
async takePhoto(options?: { autofocus?: boolean; destination?: 'card' | 'computer' }): Promise&lt;Photo&gt;
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| **options.autofocus** | `boolean` |  | Focus before the release. Defaults to `true`. |
| **options.destination** | `'card' \| 'computer'` |  | `card` (the default) keeps it on the card; `computer` also returns its bytes as `data`. |

The photo carries its `mediaId`, `name` and `sizeBytes`, the same id `listMedia()` reports.

### getLiveViewFrame

The current picture as a JPEG, with the camera's focus frames (0–1 from the top-left) and, with
`overlay`, the camera's on-screen info as a PNG (where `operations.getLiveViewFrame.options.overlay`
is supported). Each call waits for the camera's next frame; turning live view and the overlay
output on and off happens inside.

```typescript
async getLiveViewFrame(options?: { overlay?: boolean }): Promise&lt;LiveViewFrame&gt;
```

## Video

### startRecording

Gets the camera ready (video mode, card destination), starts, and resolves once the camera reports
recording. Record is sent once and never repeated. On the command line, `start-recording` stays in
the foreground and stops on Ctrl-C or after `--duration`.

```typescript
async startRecording(): Promise&lt;void&gt;
```

### stopRecording

Stops, waits until a finished clip is on the card, puts the camera back, and resolves to the clip.
Always allowed, never waits behind another operation, and never resent.

```typescript
async stopRecording(): Promise&lt;Clip&gt;
```

### getRecordingState

```typescript
async getRecordingState(): Promise&lt;'idle' | 'starting' | 'recording' | 'stopping' | 'unknown'&gt;
```

What the camera reports now. Unknown never counts as idle.

## Card and media

```typescript
async getCardStatus(): Promise&lt;CardStatus[]&gt;
async listMedia(): Promise&lt;MediaItem[]&gt;
async getMediaPreview(id: string, size?: 'thumbnail' | 'preview'): Promise&lt;Uint8Array&gt;
async downloadMedia(
  id: string,
  options?: { onProgress?: (receivedBytes: number, totalBytes: number) => void; signal?: AbortSignal }
): Promise&lt;Uint8Array&gt;
```

`getCardStatus` reports each card slot's free space, photos left and recording time left, as far as
the camera reports them. `listMedia` lists photos and clips newest first. Media ids survive a
reconnect while the file stays on the card. Nothing on the card is ever deleted or changed.

## Body

```typescript
async getBattery(): Promise&lt;Battery&gt;
async setClock(moment?: Date): Promise&lt;void&gt;
```

`getBattery` gives the level, minutes left and whether the camera is on battery, USB or DC power,
for the fields the camera reports. `setClock` sets the camera's date and time, now by default.

## Events

```typescript
on(event: 'settingsChanged' | 'mediaAdded', handler: () => void): void
off(event: 'settingsChanged' | 'mediaAdded', handler?: () => void): void
```

`settingsChanged` fires when a setting changes on the camera and `mediaAdded` when a new photo or
clip lands; read `getCapabilities()` or `listMedia()` for what changed. `off` without a handler
removes every handler of the event. Events are library only: callbacks cannot cross a process.
A raw `EventDefinition` from `protocolSession(camera).registry.events` is accepted too, for bench
work.

## Workflows

`runBenchmark(camera, { photo, liveView })` reads everything the camera reports and, when asked,
tries a photo and a live-view frame (`camera_run_benchmark`, `darkgrade telemetry benchmark`).
Workflows are functions that take a `Camera` rather than methods on it.

## Protocol access

Raw PTP operations, property reads and writes, the registries and the vendor driver classes are
not part of `Camera`. For bench work they are on `protocolSession(camera)` from the unsupported
`@darkgrade/slate/protocol` entry: `send`, `get`, `set`, `readValue`,
`getStandardPropertyStates`, `setStandardProperty`, Sony buttons and menu sessions, Canon network
state, magnification and pan, and the driver itself. They share the Camera's session, follow the
vendors' own names and are not confirmed the way `Camera` operations are.

```typescript
import { protocolSession, SonyCamera } from '@darkgrade/slate/protocol'

const driver = protocolSession(camera).driver
if (driver instanceof SonyCamera) console.log(driver.registry.properties.PositionKeySetting.name)
```
