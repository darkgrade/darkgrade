---
title: "PTP/IP over Wi-Fi"
description: "Connect over the standard PTP/IP command and event channels instead of USB (Node.js)."
---

Slate can use the standard PTP/IP command and event channels instead of USB. Bind the socket to a secondary adapter so joining a camera access point cannot move the controller's normal route:

```typescript
import { Camera } from '@darkgrade/slate'
import { IPTransport, VendorIDs } from '@darkgrade/slate/protocol'

const host = '192.168.1.1' // camera address after Wi-Fi pairing
const localAddress = '192.168.1.2' // address assigned to the isolated adapter
const transport = new IPTransport({
    address: host,
    localAddress,
    clientName: 'Darkgrade controller',
})
const camera = new Camera({ transport, vendorId: VendorIDs.CANON })

await camera.connect({ device: { ip: { host, port: 15740, protocol: 'ptp/ip', localAddress } } })
const { manufacturer, model, firmware, connection } = await camera.getInfo() // connection is 'ip'
await camera.autofocus()
await camera.disconnect()
```

Canon sessions keep the body awake by themselves: an open session sends the advertised KeepDeviceOn every ten seconds (`new Camera({ keepAlive: false })` turns this off). A one-off KeepDeviceOn for bench work is `protocolSession(camera).keepDeviceOn()` from the unsupported `@darkgrade/slate/protocol` entry.

The transport pairs separate command and event TCP connections, uses a stable client identity, supports camera-to-host and host-to-camera data phases, responds to PTP/IP ping packets, and handles fragmented or coalesced TCP frames. It is Node.js-only because it uses `node:net`. The camera must first expose its PTP/IP service and may require approval on its body; on the EOS 80D that means **Wi-Fi function → Remote control (EOS Utility) → Easy connection** after physically disconnecting USB.

## What has been verified

This transport is validated against a two-channel, Canon-oriented simulator. That proves
protocol behavior; it is not a successful physical Wi-Fi session. First pairing with a
physical EOS 80D is not yet verified.

Sony's current PC Remote over Wi-Fi uses access authentication, which `IPTransport` does
not implement. See [Sony Wi-Fi](/slate/getting_started/sony-wifi-wip) for that path and its limits.
