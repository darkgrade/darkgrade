# Test Bench workflow qualification

Simulation Bench must exercise the Darkgrade methods that Test Bench actually calls, including their session setup, state readback and cleanup. Passing a raw operation replay does not qualify the corresponding application action. The [darkgrade01 workflow record](evidence/darkgrade01-workflows-2026-10-28.md) pins the deployed bench and library versions, dispatch paths, observed DTOs and physical boundaries.

**PR #18 remains separate.** Its recording/workflow modules are absent from this branch. The gap report, UI and gaps API explicitly retain this incomplete workflow qualification; a green simulation run is not a public-release recording or collection qualification.

The baseline's ordinary Sony `camera_controls`/`camera_set_iso` uses native `SonyCamera` USB/PTP. It is not the Sony SDK recording path. A single Canon setter can perform two PTP sessions: readiness probe, then remote/event initialization, property-cache reads, write, fresh readback and close. Do not flatten those into one accepted write.

The portable public-controls scenario discovers legal choices, changes ISO, freshly reads the descriptor, restores the original value in `finally`, verifies restoration and disconnects. It also rejects unavailable choices, read-only properties and unadvertised controls before a write. Responses come from the protocol simulator, with no replacement for `Camera.send` or its codecs. It intentionally does not model the bench's HTTP dispatch, subprocess locks or vendor recording bridge.

## Recording integration contract after PR #18

The separate source at `fix/demo-shot-tuning` contains `src/camera/video-recording.ts`, `src/vendors/sony/video-recording.ts` and `src/workflows/video-take.ts`. Keep those modules and their tests in that workstream until its integration is requested. Once available, run the same public interfaces used by the bench:

1. **Prepare:** fresh recording state, selected writable card/free space, baseline object identities; preserve existing recordings. Sony's SDK media-index reserve boundary is a distinct prerequisite.
2. **Start:** use the appropriate Canon movie-mode setup, Nikon path or Sony SDK connection; require recording-state evidence. Acknowledgement without telemetry stays unconfirmed.
3. **Stop:** handle a start that failed after acceptance, repeated stop, late finalization and loss of the SDK session. Unknown stop state keeps ownership and must not permit power recovery or collection.
4. **Discover and collect:** new original identity, filename and positive safe size; distinguish delayed indexes from missing footage. Refuse changed identities, zero/oversized chunks, partial transfers and unsupported large-file addressing. Keep progress and recoverable state; finalize only a complete original.
5. **Cleanup:** independently restore camera modes/settings, release listeners/connections/locks and finish the job. Retain operation and cleanup errors; verify final state rather than inferring it from a resolved promise.

Port the existing PR #18 recording, Nikon status, Sony recording and `VideoTake` regressions alongside integration. Add recorded vendor-state scenarios through the real adapters rather than replacing recorders with success-returning stubs. Hardware runs must use the bench's current shared ownership API, target exact model/firmware/transport and preserve raw evidence privately. The older darkgrade01 deployment does not expose that ownership adapter, so it was operated only through normal MCP controls.

## Capturing enough evidence

The new physical baseline includes exact Canon Kelvin `0x9110` host bytes and acknowledgement, independent setting readbacks, preview dimensions/hashes and a short movie's metadata. Linux usbmon omitted scatter-gather bulk-IN buffers, including DeviceInfo and property-cache payloads. These files have no truncated packet records: increasing snaplen or changing the parser cannot recover bytes that the kernel never copied.

Use a reviewed application-level protocol observer or validate a compatible capture backend to obtain those missing bytes. Keep raw-wire evidence, API DTOs and physical effects as separate observations. Do not synthesize camera cache/media datasets from DTOs and label them captured. Future public Test Bench submissions need their original source revision/time, exact identity and firmware, workflow stages, readback/cleanup outcomes and sanitized evidence boundaries; imported files alone do not authenticate hardware execution.

Outpost and Fleet should consume these workflow results and request guarded hardware runs from Test Bench. Camera behavior remains in Darkgrade; application progress, run history and evidence retention belong to the host. See [the integration boundary](simulation-bench-outpost.md).
