One camera API for every brand

Studio, the MCP tools, the CLI and Test Bench now call one vendor-independent Camera. Camera hands each call to the driver for the attached brand. MCP tools and CLI commands are generated from Camera itself, so every surface uses the same names.

public APIinternalgenerated at build timefor benches, unsupported

What changed

  • One Camera for every brand. It has 25 operations: connect, focus, zoom, photo, live view, record, card and media, battery, clock. It also has setControl and typed setters such as setShutterSpeed('1/250'), which only accept values the vendor codecs can produce. Vendor-named methods are gone from Camera, and raw access lives in @darkgrade/slate/protocol.
  • Every outcome is one of three errors: unsupported, refused or outcome unknown. getCapabilities() says what works right now, and why not.
  • MCP and the CLI are generated from Camera. That gives 83 tools and commands with the library's names; none are written by hand. Studio's MCP server uses the same tools.
  • Each brand lives in one folder, vendors/<brand>/, with its definitions, its driver and its settings map.
  • Photos and clips are confirmed by the camera's own events, not by scanning the card.
  • Studio uses Slate's control list. Its sandboxed preload works again (the window had been blank since darkgrade/darkgrade#113).
  • Real-camera checks: camera:api-check calls every public method on each attached camera, all in parallel, in about 40 s. camera:parity lists what Canon and Nikon are missing against Sony. The old hardware vitest files and the smoke and verify scripts are gone.
  • Tests were audited case by case, cutting 1,380 cases to 1,075.
